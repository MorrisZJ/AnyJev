# Roadmap

This file is the plan; `CHANGELOG.md` is what landed. A box is ticked only when the code, its tests, the result JSON and the doc line are all on `main`. There are no dates here: the only target is the version at the top of each section. Items marked **help wanted** are one-file PRs; the list at the bottom says which file.

Levels, for reading the items below: `raw` (softmax over label tokens), `L0` (zero-label debiasing), `L1` (temperature on labels), `L2` (a closed-form head on the hidden state at one block, 100–300 labels per question), `auto` (a request: L2 where a head routes, else L1, else L0). `docs/levels.md` is the contract, `docs/method_v3.md` the method.

## Shipped

Version 0.1 items are on `main` and go out with the 0.1.0 release.

- [x] **L0, zero-label debiasing** (0.0.2). Cyclic-shift marginalisation over option positions plus a label-prior correction (batch prior by default, content-free opt-in); every `Decision` carries its level. Measured in [docs/results_bench.md](docs/results_bench.md) and [docs/results_typed.md](docs/results_typed.md).
- [x] **L1, temperature on labels** (0.0.2). Artifacts keyed by (model, question); since 0.1 the prior is frozen into the artifact, so an L1 decision is a pure function of its calibration set.
- [x] **Backends** (0.0.2). transformers (`HFBackend`), vLLM OpenAI-compatible server (`VLLMBackend`, `allowed_token_ids`, parity script), and a synthetic biased `FakeBackend` for CPU tests.
- [x] **Benches** (0.0.2). Three tasks with every ablation from the same forward passes; LocalLLaMA/typed-decisions with Laya's checkpoints rerun on the same decisions; NanoJev's maze harness with their own baseline rerun ([docs/results_maze.md](docs/results_maze.md)).
- [x] **Shared-prefix scoring** (0.1). The state is computed once and the K option layouts are scored against its KV; latency column in [docs/results_latency.md](docs/results_latency.md).
- [x] **Adaptive shifts, opt-in** (0.1). Shifts read in a spread order and stopped when they agree after prior correction; cost in [docs/results_adaptive.md](docs/results_adaptive.md).
- [x] **Enforceable levels** (0.1). `decide(..., require="L1")` raises `LevelError` below the asked level.
- [x] **Batch prior at strength 0.75 by default** (0.1). Chosen by an offline replay of every prior rule on 230 (model, question) units; when L0 helps and when it does not: [docs/when_l0_helps.md](docs/when_l0_helps.md).
- [x] **L2: closed-form heads at one fixed block per model** (0.1). `Decider.fit_head` solves a shrunk-LDA or ridge head on the last-position hidden state; the forward stops at that block (`blocks_executed` in the diagnostics). typed-decisions: 0.730 / 0.786 / 0.771 / 0.799 / 0.798 for Qwen3-1.7B / 4B / 8B / 30B-A3B / 32B at 64–83% of depth, from [docs/results_exit.md](docs/results_exit.md).
- [x] **Routing** (0.1). `Decider.route(q)` serves a question from its exact head, else from the same options under another wording, else from the same option set in another order; `level="auto"` falls back to L1 / L0 where no head applies.
- [x] **Label-free test-time adaptation** (0.1). `Decider(adapt="routed")` re-estimates a routed head's feature mean and scale from the unlabelled states it is asked on (30 by default); on Qwen3-8B a reworded question goes from 0.65–0.70 (head as is) to 0.74–0.75 with 30 unlabelled states, `bench/results_paraphrase/2026-09-22/`; `docs/jev_mode.md`.
- [x] **Closed-form distillation** (0.1). `bench.synth_states` writes new cases, `bench.distill_heads` labels them with a teacher's heads and solves student heads; the 32B's heads lift the 1.7B from 0.730 to 0.760 (`bench/results_distill/2026-09-22/`, research log entry 14).
- [x] **Five shipped artifact sets** (0.1). `anyjev-heads/<model>.json` for the 20 typed questions and the three bench tasks, built and validated through the user path by `scripts/build_heads.py`; arrays stored as base64 float32, 1.8–4.4 MB per model.
- [x] **Games as decision benchmarks** (0.1). 2048 and Minesweeper with built-in oracles (`demo/games/`), the maze harness with full trajectories; all run on the CPU fake backend.
- [x] **Second-run reproduction; bench and docs regenerated from JSON** (0.1). Every table comes from committed JSON, all but `docs/results_adaptive.md` and `docs/results_latency.md` via `bash scripts/regen_docs.sh` (those two carry their own regeneration command); every result JSON records batch size, dtype, backend, versions and commit.
- [x] **Clean version-3 tree** (0.1). The universal head, the cascade, the zero-label-teacher study and the early head study are gone from the code; block-loop extraction and pool caching live in `bench/pools.py` with the CLI `bench/extract_pools.py`; only result directories a shipped doc or table generator cites are kept, and everything dropped is listed in [docs/migration_v3.md](docs/migration_v3.md).
- [x] **The two diagrams in the README** (0.1). One for the fit-then-adapt loop (labels → closed-form head → routed / adapted from traffic → labels only for a new question), one for the deployment lifecycle (day 0 at L0 → collect → head → serve → new wording / new question / new model); Mermaid in `README.md` and `README.zh-CN.md`, the full flows in `docs/method_v3.md` section 5.
- [x] **Packaged L2 demo** (0.1). `python -m demo.jev_mode` fits a head on a small labelled set, decides, rewords the question and shows `routed_from` / `adapted` / `adapt_n` moving, then reloads a shipped artifact; `--backend fake` on CPU in seconds (runs in CI), `--model` on a GPU with the shipped heads, `--state-file` for your own state. The committed transcripts of real runs are `demo/results/jev_mode_Qwen__Qwen3-4B.json` (the GPU default, and the source of the README demo table) and `jev_mode_Qwen__Qwen3-1.7B.json`, plus `jev_mode_lifecycle_Qwen__Qwen3-4B.json` and `jev_mode_lifecycle_Qwen__Qwen3-1.7B.json` for `--lifecycle`.
- [x] **Online label collection: `Decider.observe`** (0.1). `observe(question, state, label)` records a labelled state and solves the question's L2 head itself once `fit_at=30` observations exist (never below max(8, 2K)), re-solving at 60, 120, ... (`refit_factor=2.0`); it returns the artifact dict on the call that (re)solved a head, else `None`; `level="auto"` answers at L0 before the first solve and at L2 after; `observations(question)` returns the stored pairs and `export_artifacts(include_observations=True)` writes them with the artifact. On `FakeBackend` a decider starts at L0 and reaches L2 by itself (`tests/test_decider_fake.py`); the demo is `python -m demo.jev_mode --backend fake --lifecycle` (also `--backend hf --questions <workflow.qname>`).
- [x] **Persist adaptation statistics** (0.1). `export_artifacts` writes, per routed question, the sum / sum of squares / count a head re-estimates its feature mean and scale from (`adaptation`, arrays in the compact format), and `load_artifacts` restores them, so a decider restarted from disk answers a reworded question adapted from its first request with the same probabilities as before the restart (identical to floating-point precision: max |dp| under 1e-50 on the synthetic model in the lifecycle demo; `tests/test_decider_fake.py`). No schema version field was added: the block is optional and older files load unchanged.

### Closed (negative results, kept in `docs/research_log.md`; not reopened without new evidence)

- [x] **Question-agnostic head**, one head for all questions: at or below L0 on every held-out question and domain, six forms tried (entries 1, 3, 9, 11; best 0.580 against L0 0.635 on Qwen3-8B, `bench/results_universal/2026-09-22/`). Heads are per question; the code is gone from the package, the extraction machinery lives on in `bench/pools.py`.
- [x] **Confidence-gated early exit** over heads at several depths: did not beat one fixed block on the 8B or the 32B (entries 4, 10; tables from `bench/results_exit/2026-09-22/Qwen__Qwen3-8B.cascade.json` and `Qwen__Qwen3-32B.cascade.json`: on the 8B the gate lands on the fixed block 22, on the 32B the best pooled rule is 0.792 at 48.9 blocks against 0.798 at the fixed block 52). The code is gone from the package, the JSON is kept.
- [x] **Distillation from a bigger model's zero-label answers**: bounded by the teacher's own accuracy; 100 gold labels (0.726) beat 300 teacher labels (0.688) (entry 7). Self-labels: 0.625 against raw 0.626 (`docs/method_v3.md` §2.5).
- [x] **Per-question block by cross-validation** (4–5 blocks deeper for no gain, entry 8) and **one head fit across several wordings** (blurs the class structure, entry 13).
- [x] **A gradient-trained linear head** on identical features: +0.002 accuracy over the closed form (entry 0). The only open form is a LoRA at the answer position (Later).

## Next

- [ ] **vLLM and SGLang coupling for L2.** Why: L2 needs the residual stream at block `b*`, and only the transformers backend exposes it, so every served deployment stops at L1. Two routes, both measured before one is chosen:
  - *Engine plugin.* A vLLM custom model runner / SGLang model hook that stops the forward at `b*` and returns the last-position residual instead of logits. Shares weights and continuous batching with the engine; but it is engine-version-specific code, must survive CUDA graphs, and a capture-only hook pays the full forward (the 0.7x comes from skipping blocks, not from reading them).
  - *Truncated checkpoint.* Export blocks `0..b*` as an ordinary HF model (final norm set to identity, or the head refit on normed features) and serve it as an embedding model with last-token pooling (`vllm serve --task embed`, SGLang `--is-embedding`); the client applies the head. No engine code, the shorter model is the saving, parity testable with `scripts/exit_parity.py`; but a second copy of `b*/N` of the weights per model, and no sharing with a generation server.
  *Done:* `Decider(VLLMBackend(...), level="L2")` and the SGLang equivalent reproduce the shipped Qwen3-4B artifact's validation accuracy within bf16 noise (|Δp| under 0.01 against the transformers path), and `docs/results_latency.md` gets a served-engine column next to the transformers one.
- [ ] **Real agentic evaluation.** Why: every number so far is a decision in isolation; the claim is about decisions inside a loop. One public agent benchmark (candidates: τ-bench for escalate and stop/continue, BFCL for tool routing; one is picked and the reason recorded), with the loop's decisions answered three ways: the same LLM generating the decision, L0, and L2 on labels collected from the baseline's own traces. Report task success, per-decision accuracy, and cost (GPU-ms and tokens per decision and per episode). *Done:* `bench/agent/` runs from one command, results JSON committed, `docs/results_agent.md` regenerated, and the README quotes it whichever way it comes out.
- [ ] **Span readout for more than 26 options.** Why: letter labels cap `choice` at 26 (the full BANKING77 and Jev's 255-option choice do not fit) and single-token labels cannot carry an exact PMI correction. Score each option string teacher-forced under the prompt (`sequence_logprobs` on the backend protocol: HF, vLLM, Fake). *Done:* the 77-way BANKING77 row runs at raw / L0 / L1 with flip and ECE, and a `FakeBackend` test with a planted length bias shows the PMI correction removing it.
- [ ] **Conformal abstention.** Why: a calibrated probability still needs a rule for "do not answer"; a split-conformal threshold turns a target error rate into one. `Decider(target_error=...)` sets `decision.abstained`; coverage-risk curve for L1 and L2 in the bench. *Done:* a `FakeBackend` test shows the realised error on answered items at or under the target on held-out synthetic data, and `cov@α` replaces the fixed `cov@5%` column.
- [ ] **More models: Llama 3.x, Gemma 3, Mistral, DeepSeek, Phi-4, gpt-oss.** Why: L2 heads ship for one family (five Qwen3 sizes); five other architectures are measured at raw / L0 / L1 only. Per model: depth curve, `b*` chosen on calibration data, artifact, latency ratio, table row; gated weights need a token, nothing else changes. *Done:* each model has `anyjev-heads/<model>.json`, `bench/results_exit/<date>/<model>.{depth,jevmode,latency}.json` and a row in `docs/results_exit.md`; no row without all three. **help wanted** per model (one GPU session; the commands are in `docs/method_v3.md` §8).
- [ ] **Technical report (arXiv).** Why: the method is spread over four docs and a 14-entry log, and the negative results deserve a citable home. Method v3, the five model tables, label efficiency, wording and order robustness, adaptation, distillation, cost, and the closed directions with their tables; every table generated from the same JSON as the docs. *Done:* the PDF builds from committed JSON, the arXiv ID is in the README citation.
- [ ] **Jev-compatible HTTP server.** Why: people integrate against the hosted API's request shape; a drop-in server lets them swap the endpoint. `POST /v1/decisions` with the decisions schema, levels in the response, `require` honoured server-side, a recorded-fixture conformance suite. *Done:* the suite passes (compatibility is advertised only then) and a chat-completions body gets a 400 with a pointer.
- [ ] **Community rows: kev, minojev, openJev Verdict, von, reflex, SemIf.** Why: the typed-decisions table has Jev (published), Laya (rerun) and us; the other open decision models belong in it on the same 2,000 decisions with their own recommended settings. *Done:* each provider is one file under `bench/providers/`, its results JSON is committed with the exact checkpoint and settings, and `bench.typed_table` prints the row. **help wanted.**
- [ ] **More log-prob backends: SGLang, llama.cpp, MLX, Ollama (L0 / L1).** Why: the contract is one method, `next_token_logprobs(prompts, token_ids)`, and each engine is a file. *Done:* a parity script like `scripts/vllm_parity.py` agrees with transformers on argmax, and an `@pytest.mark.engine` smoke test exists. **help wanted.**

## Later

- [ ] **Multimodal states.** Why: agent decisions are often about a screenshot or a frame; the question, the readout and the levels do not change, only the prompt builder and the backend. Vision backends (`AutoModelForImageTextToText`: Qwen-VL, Gemma 3), one image task with ground truth (game frames, document screenshots); raw / L0 / L1 first, L2 where the backend exposes hidden states. *Done:* one image task with committed JSON at raw / L0 / L1, flip and ECE reported as for text.
- [ ] **Quantization vs calibration.** Why: decision readout is prefill-only and compute-bound, the regime where FP8 / W4 pay, and whether heads and temperatures survive a precision change is unmeasured. *Done:* one model's accuracy and ECE at bf16 / FP8 / W4 with the bf16 head as is and refit, from JSON.
- [ ] **MoE cost on a served backend.** Why: the 30B-A3B's cost cell is empty because eager-mode transformers does not reflect 3B active parameters. *Done:* ms per decision at block 40 against the full forward on vLLM or SGLang (needs the coupling above), and the cell is filled.
- [ ] **Chained-decision bench.** Why: a 95 percent judge applied 20 times is 36 percent end to end; with calibrated per-step probabilities the compounded risk is predictable, and that prediction has not been tested. *Done:* a task with chained decisions (the maze, a multi-step workflow) reports predicted against realised end-to-end error per level.
- [ ] **Distillation on real unlabelled states.** Why: synthetic states from an 8B generator stayed 6–9 points below real ones (entry 14); the teacher head labelling real unlabelled traffic is the untested variant. *Done:* the 1.7B student measured with gold plus teacher-labelled real states against gold plus synthetic, same labels, same test set.
- [ ] **LoRA at the answer position vs the closed form.** Why: a gradient-trained linear head gained +0.002 on identical features (entry 0); whether a small adapter buys anything at the same labels is the remaining question. *Done:* both measured at the same labels and block with a paired CI, whichever way it goes.
- [ ] **Label-free skew estimate for the batch prior.** Why: the batch prior hurts when the true label marginal is skewed and no label-free rule tells that case from a biased model today (`docs/when_l0_helps.md`). *Done:* a rule replayed on the same 230 units beats strength 0.75 on the worst case without losing the mean, or the item is closed.
- [ ] **Dirichlet calibration and histogram binning** as L1 alternatives, and **multilingual slices** (MASSIVE intents; Chinese and Korean where the datasets allow). *Done:* an analytic `FakeBackend` test per method; a task file plus its license line per slice. **help wanted.**

## Non-goals

No base-model training, no prompt-compilation framework, no routing or gateway logic beyond routing a question to its own head. Those belong upstream or downstream of a decision layer.

## How items move

An item moves from Next to Now when someone is working on it, and from Now to Shipped when its definition of done is met on `main`. A result row is a committed JSON plus the command that produced it, with hardware and versions; if a run did not happen, the cell is empty. `CONTRIBUTING.md` has the file contracts.
